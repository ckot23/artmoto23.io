# Наклейки на заказ — сайт-конструктор

Сайт считает цену наклейки на плёнке ORACAL и принимает заявки: посетитель собирает
заказ в конструкторе, на вкладке **«Оставить заказ»** оставляет контакты, а заявка
уходит менеджеру в Telegram через бота.

Всё работает без сборщиков и зависимостей: `index.html` — сам сайт, `server.js` —
маленький сервер на Node 18+, который отдаёт страницу и принимает заявки.

## Быстрый старт

```bash
cp .env.example .env      # и впишите свои BOT_TOKEN и MODERATOR_ID
node server.js            # http://localhost:8080
```

Проверить логику без сети (прайс, расчёт, валидация, текст заявки):

```bash
node server.js --selftest
```

Проверить, что заявка реально доходит до модератора (Telegram не нужен —
он подменяется заглушкой):

```bash
npm test          # selftest + сквозная проверка приёма заказов
npm run test:e2e  # только сквозная проверка
```

## Что где лежит

| Файл            | Назначение                                                         |
| --------------- | ------------------------------------------------------------------ |
| `index.html`    | Весь сайт: вкладки «Конструктор» и «Оставить заказ», расчёт, превью |
| `server.js`     | Сервер: статика, `POST /api/order`, приём заказов из Telegram       |
| `pricing.js`    | Прайс и расчёт цены на сервере (копия констант из `index.html`)     |
| `tests/e2e.js`  | Сквозная проверка: заявка действительно уходит модератору           |
| `.env`          | Секреты: токен бота и id модератора. В git не попадает              |
| `orders.jsonl`  | Журнал заявок рядом с сервером (тоже не коммитится)                 |

## Как работает отправка заказа

1. Посетитель заполняет контакты на вкладке «Оставить заказ» и жмёт «Отправить заказ».
2. Браузер отправляет `POST /api/order` на `server.js`.
3. Сервер **заново** проверяет поля и **сам считает цену** (`pricing.js`) — данные
   из браузера не считаются доверенными. Если клиент видел другую сумму, в заявке
   будет пометка «проверьте расчёт».
4. Сервер отправляет заявку в Telegram методом `sendMessage` модератору.
5. Клиент видит экран «Заявка отправлена» с номером заказа.

Если вебхук настроен, сайт при этом не раскрывает токен бота: он живёт только на сервере.

В Mini App (`Telegram.WebApp`) контакт подставляется из профиля. Если сервер заявок
недоступен, срабатывает запасной путь — `tg.sendData()`: заказ приходит боту сообщением,
и сервер забирает его через `getUpdates` (`POLL=auto` по умолчанию — слушаем сами,
если вебхук не установлен).

### Если сайт на GitHub Pages, а Node-сервера нет

GitHub Pages отдаёт только статические файлы: он не может отправить сообщение в
Telegram, потому что это делает `server.js` методом `sendMessage`. Поэтому у
посетителя есть два пути, и оба уже встроены в сайт:

| Как открыт сайт | Что происходит | Нужен ли публичный сервер |
| --------------- | -------------- | ------------------------- |
| Обычный браузер | `POST /api/order` → 404 → посетитель видит кнопку **«Отправить заявку в Telegram»**: открывается чат @ckot_23 с уже готовым текстом заявки, остаётся нажать «Отправить» | нет |
| Mini App внутри Telegram (кнопка у бота) | сайт вызывает `tg.sendData()`, бот забирает заказ через `getUpdates` и пересылает модератору | публичный адрес не нужен, но где-то должен быть запущен `node server.js` с тем же `BOT_TOKEN` и `POLL=auto` |

Если запустить `server.js` на публичном HTTPS-хостинге и прописать его в
`<meta name="api-base">`, заказ с сайта уходит модератору автоматически, без
лишних нажатий — это лучший вариант (см. «Развёртывание сервера заявок»).
Кнопка ручной отправки при этом остаётся запасным путём на случай, если сервер лёг.

Два правила, без которых заявка теряется молча:

* `tg.sendData()` работает **только внутри Telegram**. В обычном браузере он ничего не
  делает, поэтому сайт больше не показывает «заявка отправлена» там, где её никто не
  получил: вместо этого посетитель видит ошибку и ссылку на @ckot_23.
* Если сайт лежит на статическом хостинге (GitHub Pages) — обязательно заполните
  `<meta name="api-base" content="https://ваш-сервер">` в `index.html`, иначе запрос
  `POST /api/order` уйдёт в никуда.

## Настройка бота

1. **Ротация токена.** Если токен где-то публиковался (переписка, скриншот, репозиторий) —
   отзовите его: @BotFather → `/mybots` → ваш бот → *API Token* → *Revoke current token*.
   Новый токен впишите только в `.env` — в `.env.example` настоящего токена быть не должно
   (это проверяет `npm run test:e2e`).
2. **Ваш chat_id.** Напишите боту `/id` — он ответит числом. Это и есть `MODERATOR_ID`.
   (Узнать id можно и у @userinfobot.) Модератор должен сам нажать «Start» у бота,
   иначе Telegram не даст боту написать ему первым.
3. **Проверка связи:**
   ```bash
   node server.js --send-test     # при DRY_RUN=0 придёт сообщение в Telegram
   ```
4. **Лог при старте.** Сервер сам проверяет бота и пишет, что происходит:
   ```
   Бот: @my_stickers_bot (id 123456789)
   Обновления: слушаю getUpdates (POLL=auto, вебхука нет) — заказы из Mini App придут сюда
   ```
   Если в логе `⚠️ Токен бота не работает: Unauthorized` — заявки до менеджера не дойдут,
   пока в `.env` не появится свежий `BOT_TOKEN`.

## Развёртывание сервера заявок (чтобы заявки уходили автоматически)

Сайт на GitHub Pages не может отправить сообщение в Telegram — для этого нужен
запущенный `server.js` с публичным HTTPS-адресом. Ниже — самый короткий путь.

### Вариант A. Render, бесплатно (≈10 минут)

В репозитории уже лежит `render.yaml`, поэтому всё сводится к нажатиям в браузере.

1. Зайдите на [render.com](https://render.com) → **New** → **Blueprint** → выберите
   свой репозиторий `artmoto23.io`. Render прочитает `render.yaml` и создаст веб-сервис.
2. Render спросит значения переменных (в файле они помечены `sync: false`):

   | Переменная       | Что вписать                                                        |
   | ---------------- | ------------------------------------------------------------------ |
   | `BOT_TOKEN`      | новый токен от @BotFather (старый отзовите, он утёк в репозиторий)  |
   | `MODERATOR_ID`   | ваш chat_id (бот `/id`)                                             |
   | `PUBLIC_URL`     | адрес сайта, например `https://ckot23.github.io/artmoto23.io`       |
   | `ALLOW_ORIGIN`   | тот же адрес сайта — иначе браузер заблокирует запрос заявки        |

   `WEBHOOK_SECRET` Render сгенерирует сам, `WEBHOOK_AUTO=1` уже прописан:
   сервер сам зарегистрирует вебхук на своём адресе.
3. Дождитесь деплоя и откройте `https://имя-сервиса.onrender.com/api/tg-check` —
   должно быть `{"ok":true,"bot":"@ваш_бот"}`.
4. Впишите адрес сервиса в `index.html` и закоммитьте:
   ```html
   <meta name="api-base" content="https://имя-сервиса.onrender.com">
   ```
   После обновления GitHub Pages заявки с сайта пойдут напрямую в Telegram.
5. Проверьте на живом сайте: заполните заказ → «Отправить заказ» → заявка должна
   прийти вам в Telegram. Если нет — смотрите лог сервиса в Render.

**Про бесплатный тариф Render:** сервис засыпает после ~15 минут простоя, и первый
запрос после сна занимает 30–60 секунд. Заявку с сайта это задержит (и сработает
запасная кнопка «Отправить заявку в Telegram»), а заявки из Mini App не потеряются:
Telegram будит сервис сам, когда присылает вебхук. Если задержки мешают — платный
план Starter или свой VPS.

### Вариант B. Railway, Fly.io, VPS, Docker

В репозитории есть `Dockerfile`, зависимостей нет — подойдёт любой хостинг с Node 18+.

```bash
# Railway: New Project → Deploy from GitHub, start command: node server.js
# Fly.io:
fly launch --no-deploy
fly secrets set BOT_TOKEN=... MODERATOR_ID=... WEBHOOK_SECRET=... WEBHOOK_AUTO=1 PUBLIC_URL=... ALLOW_ORIGIN=...
fly deploy

# Свой VPS/Docker:
docker build -t artmoto23-orders .
docker run -d -p 8080:8080 --env-file .env --restart unless-stopped artmoto23-orders
```

Требования к площадке: публичный **HTTPS** (Telegram не принимает вебхук по http),
переменные окружения из `.env.example`, один запущенный экземпляр.

### Общие настройки после развёртывания

* На сервере задайте `DRY_RUN=0` — иначе заявки пишутся только в лог.
* Вебхук ставится сам при `WEBHOOK_AUTO=1`, `WEBHOOK_SECRET=<любая строка>` и
  `SERVER_URL=<адрес сервера>` (на Render адрес подставляется автоматически).
  Вручную: `node server.js --webhook https://ваш-домен/api/tg-webhook`, снять —
  `node server.js --unwebhook`.
* **Mini App:** @BotFather → `/mybots` → ваш бот → *Bot Settings* → **Domain** →
  адрес сервера; там же *Menu Button* → тот же адрес. После этого сайт открывается
  кнопкой прямо в Telegram, а заказы приходят через вебхук.
* Проверка в любой момент: `GET /api/tg-check` — жив ли токен и видит ли сервер Telegram.
* Журнал заявок: `orders.jsonl` рядом с сервером. На бесплатном Render файловая
  система временная, поэтому там `LOG_ORDERS=0` — заявки видны в логах сервиса.

## Заявка не дошла до менеджера — что проверить

| Симптом                                            | Причина и лечение                                                     |
| -------------------------------------------------- | --------------------------------------------------------------------- |
| В логе `⚠️ Токен бота не работает`                  | Токен отозван или скопирован с ошибкой → новый у @BotFather → `BOT_TOKEN` |
| В логе `MODERATOR_ID указан неверно: chat not found`| Напишите боту `/id` и впишите полученное число                        |
| В логе `бот не может написать этому получателю`     | Модератор должен открыть бота и нажать «Start»                        |
| Сайт на GitHub Pages, в консоли браузера 404        | Не заполнен `<meta name="api-base">` в `index.html`; посетителю предлагается кнопка ручной отправки в Telegram |
| Заявки из браузера не приходят, хотя сервер запущен | Сервер без публичного HTTPS: GitHub Pages не видит `localhost` — нужен хостинг либо Mini App |
| В логе `Обновления: не принимаю (POLL=0)`           | Заказы из Mini App теряются: поставьте `POLL=auto`                    |
| В логе `у бота уже установлен вебхук`               | Вебхук и `getUpdates` одновременно не работают: `node server.js --unwebhook` |
| Заявка ушла, а в Telegram пусто                     | Запустите `node server.js --send-test` — он покажет ответ Telegram с подсказкой |

## Режимы

| Переменная   | Что делает                                                              |
| ------------ | ----------------------------------------------------------------------- |
| `DRY_RUN=1`  | Заявки не уходят в Telegram: печатаются в консоль и пишутся в `orders.jsonl`. Удобно для проверки сайта |
| `DRY_RUN=0`  | Боевой режим — заявки приходят модератору                                |
| `POLL=auto`  | По умолчанию: вебхук установлен — работаем через него, нет вебхука — слушаем `getUpdates` сами (нужно для заказов из Mini App) |
| `POLL=1`     | Всегда слушать `getUpdates`                                              |
| `POLL=0`     | Не принимать обновления Telegram (заказы из Mini App потеряются)         |
| `ALLOW_ORIGIN` | Если сайт открыт с другого домена (GitHub Pages), укажите его origin, например `https://artmoto23.github.io` |
| `LOG_ORDERS=0` | Отключить запись в `orders.jsonl`                                     |

## Mini App в Telegram

Чтобы открыть сайт как мини-приложение: @BotFather → `/newapp` (или *Bot Settings →
Menu Button*), укажите адрес, по которому доступен `server.js` (нужен HTTPS — подойдёт
любой хостинг с Node: VPS, Render, Railway, Fly.io).

Варианты приёма заказов из Mini App:

* **Polling** — по умолчанию (`POLL=auto`): сервер сам слушает `getUpdates`.
  Ничего настраивать не нужно, но запущенным должен быть только один сервер.
* **Вебхук** — если сайт доступен по HTTPS:
  ```bash
  WEBHOOK_SECRET=любая-строка node server.js --webhook https://ваш-домен/api/tg-webhook
  node server.js --unwebhook     # отключить
  ```

## API

| Метод и путь         | Назначение                                                        |
| -------------------- | ----------------------------------------------------------------- |
| `GET /api/health`    | `{ok, dry_run, token, moderator, poll, updates, order_path}` — проверка конфигурации |
| `GET /api/tg-check`  | Проверка бота: `{ok, bot, error, dry_run, updates}` — жив ли токен  |
| `POST /api/order`    | Приём заявки с сайта; возвращает `{ok, order_id, total, dry_run}`  |
| `POST /api/tg-webhook` | Вебхук Telegram (требует `WEBHOOK_SECRET`)                      |

Тело заявки:

```json
{
  "film": "matte", "design": "own", "color": "black", "shape": "rectangle",
  "w": 30, "h": 15, "qty": 10,
  "name": "Иван", "contact": "@ivan_2281", "delivery": "Москва, СДЭК",
  "comment": "нужно к пятнице", "client_total": 18450
}
```

Ограничения: не больше 8 заявок с одного IP за 15 минут, тело запроса до 64 КБ,
поля проверяются и обрезаются по длине.

## Безопасность

* Токен бота — **только** в `.env` на сервере. В `index.html` его быть не должно:
  всё, что попало в страницу, доступно любому посетителю.
* `.env`, `server.js`, `orders.jsonl` и любые файлы, начинающиеся с точки, сервер
  наружу не отдаёт.
* `WEBHOOK_SECRET` защищает вебхук от поддельных обновлений.
* Текст заявки экранируется перед отправкой в Telegram (`parse_mode=HTML`).
* Перед публикацией в открытый репозиторий проверьте `git status`: `.env` не должен
  попадать в коммит (это уже прописано в `.gitignore`).

## Прайс

Цена = `площадь × ставка плёнки × множитель дизайна × наценка за цвет`, округление
до 5 ₽, минимум 300 ₽ за заказ. Скидки за тираж: от 5 шт — 10 %, от 10 — 18 %,
от 25 — 25 %, от 50 — 32 %, от 100 — 40 %. Разработка макета — 1 500 ₽.

Таблица живёт в двух местах: `pricing.js` (сервер) и внутри `index.html` (фронтенд,
чтобы сайт работал без запросов к API). Тест `node server.js --selftest` сравнивает
обе копии — если правите прайс, правьте оба файла и запускайте тест.
