# Наклейки на заказ — сайт-конструктор

Сайт считает цену наклейки на плёнке ORACAL и принимает заявки: посетитель собирает
заказ в конструкторе, на вкладке **«Оставить заказ»** оставляет контакты, а заявка
уходит менеджеру в Telegram через бота.

Всё работает без сборщиков и зависимостей: `index.html` — сам сайт, `server.js` —
маленький сервер на Node 18+, который отдаёт страницу и принимает заявки.

## Быстрый старт

```bash
cp .env.example .env      # и впишите свои BOT_TOKEN и MODERATOR_ID
node server.js            # http://localhost:8080
```

Проверить логику без сети (прайс, расчёт, валидация, текст заявки):

```bash
node server.js --selftest
```

Проверить, что заявка реально доходит до модератора (Telegram не нужен —
он подменяется заглушкой):

```bash
npm test           # всё: сервер, бот, панель и вход в админку по паролю
npm run test:admin # только вход по паролю: шифрование, блокировка, смена пароля
npm run test:templates # только галерея: фото, каталог, архив, публикация
npm run test:e2e   # только сквозная проверка приёма заказов
```

## Как работает отправка заказа

1. Посетитель заполняет контакты на вкладке «Оставить заказ» и жмёт «Отправить заказ».
2. Браузер отправляет `POST /api/order` на `server.js`.
3. Сервер **заново** проверяет поля и **сам считает цену** (`pricing.js`) — данные
   из браузера не считаются доверенными. Если клиент видел другую сумму, в заявке
   будет пометка «проверьте расчёт».
4. Сервер отправляет заявку в Telegram методом `sendMessage` модератору.
5. Клиент видит экран «Заявка отправлена» с номером заказа.

Если вебхук настроен, сайт при этом не раскрывает токен бота: он живёт только на сервере.

В Mini App (`Telegram.WebApp`) контакт подставляется из профиля. Если сервер заявок
недоступен, срабатывает запасной путь — `tg.sendData()`: заказ приходит боту сообщением,
и сервер забирает его через `getUpdates` (`POLL=auto` по умолчанию — слушаем сами,
если вебхук не установлен).

### Если сайт на GitHub Pages, а Node-сервера нет

GitHub Pages отдаёт только статические файлы: он не может отправить сообщение в
Telegram, потому что это делает `server.js` методом `sendMessage`. Поэтому у
посетителя есть два пути, и оба уже встроены в сайт:

| Как открыт сайт | Что происходит | Нужен ли публичный сервер |
| --------------- | -------------- | ------------------------- |
| Обычный браузер | `POST /api/order` → 404 → посетитель видит кнопку **«Отправить заявку в Telegram»**: открывается чат @ckot_23 с уже готовым текстом заявки, остаётся нажать «Отправить» | нет |
| Mini App внутри Telegram (кнопка у бота) | сайт вызывает `tg.sendData()`, бот забирает заказ через `getUpdates` и пересылает модератору | публичный адрес не нужен, но где-то должен быть запущен `node server.js` с тем же `BOT_TOKEN` и `POLL=auto` |

Если запустить `server.js` на публичном HTTPS-хостинге и прописать его в
`<meta name="api-base">`, заказ с сайта уходит модератору автоматически, без
лишних нажатий — это лучший вариант (см. «Развёртывание сервера заявок»).
Кнопка ручной отправки при этом остаётся запасным путём на случай, если сервер лёг.

Два правила, без которых заявка теряется молча:

* `tg.sendData()` работает **только внутри Telegram**. В обычном браузере он ничего не
  делает, поэтому сайт больше не показывает «заявка отправлена» там, где её никто не
  получил: вместо этого посетитель видит ошибку и ссылку на @ckot_23.
* Если сайт лежит на статическом хостинге (GitHub Pages) — обязательно заполните
  `<meta name="api-base" content="https://ваш-сервер">` в `index.html`, иначе запрос
  `POST /api/order` уйдёт в никуда.

## Меню админа: вход по паролю

Всё, что касается бота, живёт за паролем на странице **`admin.html`** — ссылка
**«Меню админа»** в блоке «Продавец» на сайте.

**Первый вход.** Страница попросит придумать пароль (минимум 6 символов, вводится
дважды) и сразу предложит заполнить настройки: **токен бота**, **chat_id модератора**
и **адрес сайта**. Больше токен нигде вводить не нужно.

**Дальше** — просто «Войти» по паролю. В меню: панель бота, «Проверить бота»
(Telegram подтверждает, что токен рабочий), настройки приёма заявок, смена пароля,
«Выйти» и «Сбросить доступ».

Как это устроено и чего ждать:

* **Пароля нет в файлах сайта.** Он хранится в браузере отпечатком
  (PBKDF2-SHA256, 150 000 итераций, случайная соль) — по отпечатку пароль не
  восстановить, и проверить его можно только вводом. Тем же паролем шифруются
  настройки (AES-GCM), поэтому токен лежит в localStorage **только зашифрованным**.
  Это проверяет `npm run test:admin`.
* **Страница статическая, поэтому пароль — ваш личный, а не «пароль для всех».**
  Он закрывает настройки и токен на вашем устройстве: посторонний, открывший
  `admin.html` в своём браузере, увидит предложение придумать свой пароль, а ваших
  настроек и токена там нет физически.
* **5 неверных попыток — пауза на 60 секунд** (страница пишет, сколько ждать),
  после каждой ошибки показывает, сколько попыток осталось.
* **Забыли пароль** — «Сбросить доступ» на экране входа удаляет пароль и настройки
  из браузера; после этого нужно задать пароль заново и ввести токен. Это быстрее,
  чем восстанавливать: пароль никуда не отправляется и восстановить его нельзя.
* **Пароль не спасает засвеченный токен.** Если токен когда-то попал в переписку,
  скриншот или старый файл — отзовите его у @BotFather (`/revoke`) и вставьте новый
  в настройках.
* **Нужен https и современный браузер** — на http-страницах браузеры не дают
  шифрование, и админка честно скажет об этом вместо того, чтобы открыться «настежь».
* **Одна сессия на вкладку:** войдя в меню, вы попадаете в панель без повторного
  пароля. Закрыли вкладку — пароль спросят снова.

## Галерея шаблонов: фото примеров и заказ в один клик

На сайте есть раздел **«Готовые шаблоны»**: клиент видит примеры работ, нажимает на
карточку — и материал, цвет, форма, размер и тираж подставляются в конструктор,
цена тут же пересчитывается. Шаблон — это не только картинка: вместе с фото хранятся
настройки заказа, поэтому карточка сразу показывает цену за тираж.

**Как добавить шаблон (меню админа → «Галерея шаблонов»)**

1. Выберите фото (JPEG, PNG или WebP) — прямо в телефоне или на компьютере.
   Браузер сам сжимает его до 1280 точек по длинной стороне, так что галерея
   остаётся быстрой.
2. Напишите название, при желании подпись, и выставьте настройки: материал, дизайн,
   цвет, форма, размер, тираж. Цена за тираж показана тут же под формой.
3. Нажмите **«Сохранить шаблон»**. Пока это черновик в вашем браузере — на сайте его нет.
4. Нажмите **«Опубликовать в GitHub»** (или скачайте архив и загрузите в репозиторий
   вручную — инструкция в самой админке, в разделе «Архив вручную»). Через 1–2 минуты
   галерея обновится на сайте GitHub Pages.

**Почему публикация, а не «загрузка на сервер».** Сайт статический, сервера нет:
браузер не может сам положить файл в чужой репозиторий. Поэтому фото и каталог
попадают в репозиторий — либо кнопкой (GitHub API по вашему токену), либо архивом
через github.com. Готовый шаблон всё равно должен лежать в репозитории: его видят
посетители, иначе галерея будет пустой у всех, кроме вас.

**Публикация в один клик.** В настройках админки есть поля «Токен GitHub»,
владелец, репозиторий и ветка. Как сделать токен: github.com → Settings →
Developer settings → **Personal access tokens → Fine-grained tokens** → доступ
только к репозиторию сайта, права **Contents: Read and write**. Токен хранится
зашифрованным вместе с остальными настройками (в файлах его нет) и даёт доступ
лишь к этому репозиторию. Кнопка «Опубликовать» сама ставит новые фото в
`templates/img/`, обновляет `templates/catalog.js` и убирает из репозитория фото
удалённых шаблонов.

**Что стоит знать**

* **Черновики живут в браузере** (около 5 МБ — примерно 10–20 фото). После публикации
  фото из браузера убираются, а в хранилище остаётся только список шаблонов.
  Если чистить историю браузера с «данными сайтов», черновики исчезнут —
  опубликованные шаблоны при этом на месте, их всегда можно вернуть кнопкой
  **«Загрузить каталог с сайта»**.
* **Фото в галерее публичны** — это товар, его видят посетители. Не загружайте туда
  чужие фото и ничего приватного.
* **Заменённое фото** подставляется в тот же шаблон и меняется на сайте при
  публикации; старое имя файла переиспользуется, поэтому ничего не «задваивается».
* **Демо-шаблоны** (кофейня, авто, витрина) нарисованы для примера — замените их
  своими фото или удалите: пока шаблонов нет, раздела на сайте просто не видно.
* Проверки галереи: `npm run test:templates` — фото из браузера, отсев чужих путей,
  запись и чтение каталога, настоящий ZIP, публикация через GitHub API (с заглушкой).

## Панель бота: запуск прямо в браузере (без хостинга, без программ)

Самый простой способ: на сайте открыть **«Меню админа»** (`admin.html`), войти по
паролю и нажать **«Панель бота — принимать заявки»**, затем **«Запустить приём
заявок»**. Панель просит тот же пароль, что и меню админа, и берёт настройки
(токен, chat_id) уже расшифрованными — поля для токена в ней нет. Пока вкладка
открыта, бот принимает заявки с сайта и пересылает их модератору.

* **Токен никуда не попадает, кроме вашего браузера.** Он лежит в localStorage
  устройства **в зашифрованном виде** (ключ — ваш пароль) и отправляется только на
  `api.telegram.org`. В файлах репозитория (а значит и для посетителей сайта) его нет
  — это проверяют `npm run test:panel` и `npm run test:admin`. Удалить настройки
  можно кнопкой «Сбросить доступ» в меню админа.
* **Вкладка должна быть открыта.** Закрыли — Telegram хранит недоставленные
  команды до 24 часов, и они придут, когда панель снова откроется.
* **Нельзя запускать два приёмника одновременно** (панель, GitHub Actions,
  `node bot.js`): Telegram отдаёт обновления только одному, второй получит
  ошибку 409 — панель объяснит это в журнале.
* Удобно держать панель под рукой на телефоне: @BotFather → `/mybots` → ваш бот →
  *Bot Settings* → **Menu Button** → адрес `.../bot.html`. Тогда панель открывается
  кнопкой в чате с ботом.

Что показывает панель: состояние приёма, счётчики (заявки, обновления, ошибки) и
журнал — по каждой заявке видно, что она ушла модератору, а по ошибкам — что именно
случилось и что делать (неверный токен, заблокированный бот, 409, обрыв сети).

## Бот без хостинга (GitHub Actions)

**Главное, что нужно понимать:** бот в Telegram не работает сам по себе. Telegram
только хранит сообщения, а читает их и отвечает тот, кто вызывает `getUpdates`.
Хостинг для этого не нужен: «сервером» становится ваш же репозиторий — GitHub
Actions по расписанию бесплатно запускает `bot.js`, забирает накопившиеся команды
и пересылает заявки модератору. Так работает путь «сайт на GitHub Pages + бот».

Что видит клиент:

1. Собирает заявку на сайте и нажимает **«Отправить заявку боту»** — Telegram
   открывает чат с ботом и показывает кнопку **ЗАПУСТИТЬ**, клиент её нажимает.
2. Бот получает команду с данными заявки, проверяет её, сам считает цену
   (`pricing.js`) и пересылает заявку модератору. Клиенту приходит номер заявки.
3. Чего в ссылке не хватило (комментарий, город) — бот спросит в чате и передаст
   дополнение модератору.

Задержка: расписание GitHub Actions — минимум раз в 5 минут, и запуск часто
сдвигается на 1–5 минут, поэтому заявка приходит обычно **за 1–6 минут**. Если
нужно срочно — на сайте рядом кнопка «Написать менеджеру @ckot_23».

### Настройка (≈5 минут)

1. Впишите юзернейм бота в `index.html` — тогда кнопки бота появятся сами
   (без `@`, например `ckot23_orders_bot`):
   ```html
   <meta name="tg-bot" content="ваш_бот">
   ```
2. Repository → **Settings → Secrets and variables → Actions → New repository secret**:

   | Секрет         | Значение                                                             |
   | -------------- | -------------------------------------------------------------------- |
   | `BOT_TOKEN`    | новый токен от @BotFather (старый отзовите — он утёк в репозиторий)   |
   | `MODERATOR_ID` | ваш chat_id (узнать: @userinfobot или бот `/id`)                      |
   | `PUBLIC_URL`   | необязательно: адрес сайта — попадёт в приветствие бота               |

3. Раздел **Actions** → workflow «Бот заявок» → **Enable workflow**, затем
   **Run workflow** — это ручная проверка: бот заберёт накопившиеся команды сразу.
4. Модератор должен открыть бота и нажать «Start» — иначе Telegram не даст боту
   написать ему первым (в логе запуска будет `бот не может написать этому получателю`).
5. Отправьте тестовую заявку с сайта: нажмите «Отправить заявку боту» → ЗАПУСТИТЬ →
   подождите до 5 минут (или запустите workflow вручную, чтобы не ждать).

Файлы, которые всё это делают: `bot.js` (транспорт для Node), `botcore.js` (общая
логика заявок), `orderlink.js` (упаковка заявки в ссылку), `env.js` (настройки),
`.github/workflows/bot.yml` (расписание). Панель браузера использует те же
`botcore.js` и `orderlink.js`, поэтому способы запуска не расходятся.

Проверить логику без сети:

```bash
node bot.js --selftest
npm run test:bot        # сквозная проверка: заявка с сайта → бот → модератор
```

### Вариант «бот на своём компьютере» (без задержки)

```bash
node bot.js             # слушает команды постоянно, заявки приходят мгновенно
```

Нужен Node 18+ и включённый компьютер. Подходит, если ждать 5 минут нельзя, а
держать сервер не хочется. Одновременно с расписанием Actions запускать не нужно:
два процесса с одним токеном мешают друг другу (`409 Conflict`).

### Ограничения, о которых стоит знать

* **Приватный репозиторий:** бесплатные минуты Actions ограничены (2000 в месяц),
  а запуск каждые 5 минут съедает около 1200 минут в сутки. Для приватного
  репозитория лучше запускать бота у себя (`node bot.js`) или реже по расписанию.
  Публичные репозитории — без ограничений.
* **60 дней простоя:** GitHub выключает расписание у неактивных репозиториев.
  Возвращается любой commit или кнопка «Enable workflow» в разделе Actions.
* **В ссылку t.me/бот?start=… Telegram пускает не больше 64 символов**, поэтому
  туда помещаются конфигурация, имя и город; контакт для связи — сам Telegram-аккаунт
  клиента (в заявке у модератора есть кнопка «Написать клиенту»). Полный текст
  с телефоном и комментарием передаёт кнопка «Поделиться заявкой в Telegram».
* **Заявки не хранятся** ни на сайте, ни в репозитории: бот сразу пересылает их
  модератору. Секреты живут только в GitHub Secrets, в код они не попадают.

## Настройка бота

1. **Ротация токена.** Если токен где-то публиковался (переписка, скриншот, репозиторий) —
   отзовите его: @BotFather → `/mybots` → ваш бот → *API Token* → *Revoke current token*.
   Новый токен впишите только в `.env` — в `.env.example` настоящего токена быть не должно
   (это проверяет `npm run test:e2e`).
2. **Ваш chat_id.** Напишите боту `/id` — он ответит числом. Это и есть `MODERATOR_ID`.
   (Узнать id можно и у @userinfobot.) Модератор должен сам нажать «Start» у бота,
   иначе Telegram не даст боту написать ему первым.
3. **Проверка связи:**
   ```bash
   node server.js --send-test     # при DRY_RUN=0 придёт сообщение в Telegram
   node server.js --doctor        # кто забирает обновления бота и нет ли второго получателя
   ```
4. **Лог при старте.** Сервер сам проверяет бота и пишет, что происходит:
   ```
   Бот: @my_stickers_bot (id 123456789)
   Обновления: слушаю getUpdates (POLL=auto, вебхука нет) — заказы из Mini App придут сюда
   ```
   Если в логе `⚠️ Токен бота не работает: Unauthorized` — заявки до менеджера не дойдут,
   пока в `.env` не появится свежий `BOT_TOKEN`.

## Развёртывание сервера заявок (чтобы заявки уходили автоматически)

Сайт на GitHub Pages не может отправить сообщение в Telegram — для этого нужен
запущенный `server.js` с публичным HTTPS-адресом. Ниже — самый короткий путь.

### Вариант A. Render, бесплатно (≈10 минут)

В репозитории уже лежит `render.yaml`, поэтому всё сводится к нажатиям в браузере.

1. Зайдите на [render.com](https://render.com) → **New** → **Blueprint** → выберите
   свой репозиторий `artmoto23.io`. Render прочитает `render.yaml` и создаст веб-сервис.
2. Render спросит значения переменных (в файле они помечены `sync: false`):

   | Переменная       | Что вписать                                                        |
   | ---------------- | ------------------------------------------------------------------ |
   | `BOT_TOKEN`      | новый токен от @BotFather (старый отзовите, он утёк в репозиторий)  |
   | `MODERATOR_ID`   | ваш chat_id (бот `/id`)                                             |
   | `PUBLIC_URL`     | адрес сайта, например `https://ckot23.github.io/artmoto23.io`       |
   | `ALLOW_ORIGIN`   | тот же адрес сайта — иначе браузер заблокирует запрос заявки        |

   `WEBHOOK_SECRET` Render сгенерирует сам, `WEBHOOK_AUTO=1` уже прописан:
   сервер сам зарегистрирует вебхук на своём адресе.
3. Дождитесь деплоя и откройте `https://имя-сервиса.onrender.com/api/tg-check` —
   должно быть `{"ok":true,"bot":"@ваш_бот"}`.
4. Впишите адрес сервиса в `index.html` и закоммитьте:
   ```html
   <meta name="api-base" content="https://имя-сервиса.onrender.com">
   ```
   После обновления GitHub Pages заявки с сайта пойдут напрямую в Telegram.
5. Проверьте на живом сайте: заполните заказ → «Отправить заказ» → заявка должна
   прийти вам в Telegram. Если нет — смотрите лог сервиса в Render.

**Про бесплатный тариф Render:** сервис засыпает после ~15 минут простоя, и первый
запрос после сна занимает 30–60 секунд. Заявку с сайта это задержит (и сработает
запасная кнопка «Отправить заявку в Telegram»), а заявки из Mini App не потеряются:
Telegram будит сервис сам, когда присылает вебхук. Если задержки мешают — платный
план Starter или свой VPS.

### Вариант B. Railway, Fly.io, VPS, Docker

В репозитории есть `Dockerfile`, зависимостей нет — подойдёт любой хостинг с Node 18+.

```bash
# Railway: New Project → Deploy from GitHub, start command: node server.js
# Fly.io:
fly launch --no-deploy
fly secrets set BOT_TOKEN=... MODERATOR_ID=... WEBHOOK_SECRET=... WEBHOOK_AUTO=1 PUBLIC_URL=... ALLOW_ORIGIN=...
fly deploy

# Свой VPS/Docker:
docker build -t artmoto23-orders .
docker run -d -p 8080:8080 --env-file .env --restart unless-stopped artmoto23-orders
```

Требования к площадке: публичный **HTTPS** (Telegram не принимает вебхук по http),
переменные окружения из `.env.example`, один запущенный экземпляр.

### Общие настройки после развёртывания

* На сервере задайте `DRY_RUN=0` — иначе заявки пишутся только в лог.
* Вебхук ставится сам при `WEBHOOK_AUTO=1`, `WEBHOOK_SECRET=<любая строка>` и
  `SERVER_URL=<адрес сервера>` (на Render адрес подставляется автоматически).
  Вручную: `node server.js --webhook https://ваш-домен/api/tg-webhook`, снять —
  `node server.js --unwebhook`.
* **Mini App:** @BotFather → `/mybots` → ваш бот → *Bot Settings* → **Domain** →
  адрес сервера; там же *Menu Button* → тот же адрес. После этого сайт открывается
  кнопкой прямо в Telegram, а заказы приходят через вебхук.
* Проверка в любой момент: `GET /api/tg-check` — жив ли токен и видит ли сервер Telegram.
* Журнал заявок: `orders.jsonl` рядом с сервером. На бесплатном Render файловая
  система временная, поэтому там `LOG_ORDERS=0` — заявки видны в логах сервиса.

## Один бот — один потребитель обновлений (ошибка 409)

Telegram отдаёт `getUpdates` только одному процессу. Если очередь уже держит кто-то
ещё, второй получает ошибку 409 — именно она выглядит как «бот перестал работать,
когда я запустил сервер»:

```
23:28:58 · getUpdates: Conflict: terminated by other getUpdates request;
make sure that only one bot instance is running
```

Одновременно могут работать сервер сайта (`node server.js`), бот в браузере
(вкладка `bot.html`), расписание GitHub Actions и `node bot.js` — но получать
обновления должен кто-то один. Кто именно занял очередь, покажет диагностика:

```bash
node server.js --doctor
```

Она печатает состояние вебхука, свободна ли очередь `getUpdates` и что сделать:
остановить Actions, закрыть вкладку или задать `SERVER_URL`.

Проект договаривается сам, чтобы вы об этом не думали:

| Кто запущен                        | Поведение при занятой очереди                                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `server.js` (постоянный сервер)    | **главный.** При 409 не забивает лог: отступает с паузой 5 → 10 → 20 → 40 → 60 с и забирает очередь, как только она освободится. Если появился вебхук (его поставил другой сервер), опрос останавливается |
| `bot.js --once` (GitHub Actions)   | перед работой спрашивает `/api/health` сервера (`SERVER_URL` или адрес из вебхука): сервер жив и сам принимает обновления — запуск пропускается. Если очередь занята 45 с подряд — уступает и завершается |
| панель `bot.html` (бот в браузере) | при 409 отступает, а после третьего раза останавливается и пишет, что обновления забирает сервер сайта                              |
| `node bot.js` (постоянный бот)     | пока сервер жив, проверяет его раз в минуту и не мешает; забирает очередь, когда сервер выключится                                  |

Заявки, отправленные кнопкой «Отправить заявку боту» и с сайта через `/api/order`,
уходят модератору напрямую — они от 409 не зависят. Под ударом только заказы из
Mini App и команды `/start` со ссылкой с сайта.

Настроить вручную:

* `SERVER_URL=https://ваш-сервер.onrender.com` — адрес сервера, который проверяет
  бот. В Actions это секрет `SERVER_URL` (Settings → Secrets → Actions).
* `YIELD_TO_SERVER=0` или `node bot.js --force` — запретить боту уступать
  (только для проверки: иначе начнётся тот самый 409).
* Остановить лишний потребитель: workflow «Бот заявок» → **Disable workflow**,
  закрыть вкладку `bot.html`, выключить второй сервер.

## Заявка не дошла до менеджера — что проверить

| Симптом                                            | Причина и лечение                                                     |
| -------------------------------------------------- | --------------------------------------------------------------------- |
| В логе `⚠️ Токен бота не работает`                  | Токен отозван или скопирован с ошибкой → новый у @BotFather → `BOT_TOKEN` |
| В логе `MODERATOR_ID указан неверно: chat not found`| Напишите боту `/id` и впишите полученное число                        |
| В логе `бот не может написать этому получателю`     | Модератор должен открыть бота и нажать «Start»                        |
| Сайт на GitHub Pages, в консоли браузера 404        | Не заполнен `<meta name="api-base">` в `index.html`; посетителю предлагается кнопка ручной отправки в Telegram |
| Заявки из браузера не приходят, хотя сервер запущен | Сервер без публичного HTTPS: GitHub Pages не видит `localhost` — нужен хостинг либо Mini App |
| В логе `Обновления: не принимаю (POLL=0)`           | Заказы из Mini App теряются: поставьте `POLL=auto`                    |
| `getUpdates: Conflict … 409`                        | Очередь держит второй потребитель: `node server.js --doctor` и раздел «Один бот — один потребитель обновлений» выше |
| В логе `у бота уже установлен вебхук`               | Вебхук и `getUpdates` одновременно не работают: `node server.js --unwebhook` (живой вебхук сервера бот и панель больше не снимают сами) |
| Заявка ушла, а в Telegram пусто                     | Запустите `node server.js --send-test` — он покажет ответ Telegram с подсказкой |

## Режимы

| Переменная   | Что делает                                                              |
| ------------ | ----------------------------------------------------------------------- |
| `DRY_RUN=1`  | Заявки не уходят в Telegram: печатаются в консоль и пишутся в `orders.jsonl`. Удобно для проверки сайта |
| `DRY_RUN=0`  | Боевой режим — заявки приходят модератору                                |
| `POLL=auto`  | По умолчанию: вебхук установлен — работаем через него, нет вебхука — слушаем `getUpdates` сами (нужно для заказов из Mini App) |
| `POLL=1`     | Всегда слушать `getUpdates`                                              |
| `POLL=0`     | Не принимать обновления Telegram (заказы из Mini App потеряются)         |
| `ALLOW_ORIGIN` | Если сайт открыт с другого домена (GitHub Pages), укажите его origin, например `https://artmoto23.github.io` |
| `LOG_ORDERS=0` | Отключить запись в `orders.jsonl`                                     |
| `SERVER_URL`   | Публичный адрес этого сервера. По нему бот (`bot.js`, GitHub Actions) проверяет, жив ли сервер, и уступает ему очередь обновлений |
| `YIELD_TO_SERVER=0` | Запретить `bot.js` уступать работающему серверу (по умолчанию уступает) |

## Mini App в Telegram

Чтобы открыть сайт как мини-приложение: @BotFather → `/newapp` (или *Bot Settings →
Menu Button*), укажите адрес, по которому доступен `server.js` (нужен HTTPS — подойдёт
любой хостинг с Node: VPS, Render, Railway, Fly.io).

Варианты приёма заказов из Mini App:

* **Polling** — по умолчанию (`POLL=auto`): сервер сам слушает `getUpdates`.
  Ничего настраивать не нужно, но запущенным должен быть только один сервер.
* **Вебхук** — если сайт доступен по HTTPS:
  ```bash
  WEBHOOK_SECRET=любая-строка node server.js --webhook https://ваш-домен/api/tg-webhook
  node server.js --unwebhook     # отключить
  ```

## API

| Метод и путь         | Назначение                                                        |
| -------------------- | ----------------------------------------------------------------- |
| `GET /api/health`    | `{ok, dry_run, token, moderator, poll, updates, order_path, updates_detail, takes_updates}` — проверка конфигурации. `updates_detail` (`mode`, `alive`, `last_ok_age_ms`, `conflicts`, `last_error`) и `takes_updates` говорят, принимает ли сервер обновления сам: по этому признаку бот и панель уступают ему очередь |
| `GET /api/tg-check`  | Проверка бота: `{ok, bot, error, dry_run, updates}` — жив ли токен  |
| `bot.html`           | Панель бота (статика): приём заявок прямо в браузере владельца       |
| `POST /api/order`    | Приём заявки с сайта; возвращает `{ok, order_id, total, dry_run}`  |
| `POST /api/tg-webhook` | Вебхук Telegram (требует `WEBHOOK_SECRET`)                      |

Тело заявки:

```json
{
  "film": "matte", "design": "own", "color": "black", "shape": "rectangle",
  "w": 30, "h": 15, "qty": 10,
  "name": "Иван", "contact": "@ivan_2281", "delivery": "Москва, СДЭК",
  "comment": "нужно к пятнице", "client_total": 18450
}
```

Ограничения: не больше 8 заявок с одного IP за 15 минут, тело запроса до 64 КБ,
поля проверяются и обрезаются по длине.

## Безопасность

* Токен бота — **только** в `.env` на сервере. В `index.html` его быть не должно:
  всё, что попало в страницу, доступно любому посетителю.
* `.env`, `server.js`, `orders.jsonl` и любые файлы, начинающиеся с точки, сервер
  наружу не отдаёт.
* **Токен GitHub** (для публикации галереи) лежит там же, где токен бота: в браузере,
  зашифрованным паролем. Сделайте его fine-grained и дайте только право
  `Contents: Read and write` на репозиторий сайта — тогда даже при утечке он не
  откроет доступ к остальным репозиториям.
* **Админка (`admin.html`) закрыта паролем владельца.** Пароль и токен не хранятся
  в файлах сайта: пароль — только отпечатком в браузере, токен — зашифрованным
  (PBKDF2-SHA256 + AES-GCM, см. `adminlock.js`). Пять неверных попыток — пауза 60 с.
* `WEBHOOK_SECRET` защищает вебхук от поддельных обновлений.
* Текст заявки экранируется перед отправкой в Telegram (`parse_mode=HTML`).
* Перед публикацией в открытый репозиторий проверьте `git status`: `.env` не должен
  попадать в коммит (это уже прописано в `.gitignore`).
